# Архитектура в нотации C4

> [!NOTE]
> **Зачем:** показать решение на четырёх уровнях масштаба — от «решение и его окружение» до «как устроено ядро в коде». Каждый уровень — отдельный короткий документ: диаграмма и одна таблица.
> **Пример заполнения:** [example/c4/](../../example/c4/README.md)

| Уровень | Вопрос | Читатель | Документ | Обязателен? |
|---------|--------|----------|----------|-------------|
| 1. Контекст | Кто пользуется решением и с какими системами оно связано? | Все, включая бизнес | [01_context.md](01_context.md) | Да |
| 2. Контейнеры | Из каких приложений и хранилищ состоит решение? | Архитектор, разработка, эксплуатация | [02_containers.md](02_containers.md) | Да |
| 3. Компоненты | Из каких частей состоит один контейнер? | Разработчики контейнера | [03_components.md](03_components.md) | Для сложных контейнеров |
| 4. Код | Как устроено ядро логики? | Разработчики | [04_code.md](04_code.md) | Только для самого важного места |

## Как рисовать

Диаграммы делаются в [C4-PlantUML](https://github.com/plantuml-stdlib/C4-PlantUML), библиотека встроена в PlantUML и подключается одной строкой: `!include <C4/C4_Context>`, `<C4/C4_Container>` или `<C4/C4_Component>`. Исходники кладите в `diagrams/c4/`.

## Типичные ошибки

- На одной диаграмме смешаны уровни: контейнеры вперемешку с классами.
- На стрелках нет подписей — непонятно, что и по какому протоколу передаётся.
- Уровни 3 и 4 нарисованы для всего подряд и быстро устаревают.
- Внешняя система оказалась внутри границы решения.

## Готово, когда

- [ ] Каждый участник раздела 4 и каждая внешняя система есть на уровне 1
- [ ] Каждый компонент раздела 6 есть на уровне 2
- [ ] На стрелках уровня 2 указаны протоколы и номера API из раздела 5
- [ ] Уровни 3 и 4 нарисованы только там, где без них непонятно
