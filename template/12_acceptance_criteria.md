# 12. Критерии приёмки

> [!NOTE]
> **Зачем раздел:** описать проверяемые результаты в формате **Дано / Когда / Тогда**. Каждое ФТ (раздел 3) и каждое бизнес-правило (раздел 10) должны быть покрыты хотя бы одним критерием.
> **Пример заполнения:** [example/12_acceptance_criteria.md](../example/12_acceptance_criteria.md)

## 12.1 Функциональные критерии

*Группируйте критерии подзаголовками по функциональным блокам, как ФТ в разделе 3.*

| ID | Связь | Дано | Когда | Тогда |
|----|-------|------|-------|-------|
| AC-01 | FR-01, BR-01 | *Исходное состояние данных и пользователя* | *Одно действие* | *Код ответа, значения полей, состояние данных после действия* |

> [!TIP]
> Колонка «Связь» обязательна: по ней скрипт проверяет покрытие. Пишите негативные критерии (ошибки, лимиты, чужие данные, гонки) так же подробно, как позитивные — именно они чаще всего ломаются.

## 12.2 Приёмка нефункциональных требований

| ID | НФТ | Как проверяется | Критерий прохождения |
|----|-----|-----------------|----------------------|
| AC-N01 | NFR-01 | *Тест, учения, ревью, мониторинг* | *Число, при котором считаем пройденным* |

## 12.3 Пример в формате Gherkin

*Критерии можно переводить в автотесты.*

```gherkin
Feature: Название функции

  Scenario: Название сценария (AC-01)
    Given исходное состояние
    When действие
    Then ожидаемый результат
```

## 12.4 Определение готовности (Definition of Done)

- [ ] Все функциональные критерии проходят на тестовом стенде
- [ ] Критерии НФТ проверены, результаты приложены
- [ ] Документация соответствует реализации
- [ ] *Другие условия: обучение, оповещения, закрытые открытые вопросы*

---

### Типичные ошибки

- «Тогда» содержит оценку («работает корректно») вместо проверяемого результата.
- В одном критерии несколько действий в «Когда» — при падении непонятно, что сломалось.
- Не описано состояние данных после действия: проверяется только ответ API.

### Раздел готов, когда

- [ ] Каждое ФТ и каждое бизнес-правило покрыто хотя бы одним критерием
- [ ] Каждое НФТ имеет критерий прохождения с числом
- [ ] `python3 tools/check_traceability.py template` проходит без ошибок
