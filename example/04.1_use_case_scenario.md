# Шаблон для детализации варианта использования (Use Case) и выведения из него интеграционного сценария.

>[!NOTE]
>Этот раздел шаблона предназаначен  для структурирования и детализации вариантов использования и последующей разработки **интеграционного сценария для решения бизнес-задачи**.
>
>На основе интеграционного сценария можно спланировать создание нового API или доработку существующего и выбрать, какие компоненты для этого взаимодействия использовать.

>[!TIP]
> Для выведения интеграционного сценария нужно:
> 1. Выбрать вариант использования (Use Case);
> 2. Детализировать сценарий, описав шаги его выполнения с точки зрения логической их последовательности;
>    * Если сценарий предполагает задействование функциональностей UI, UX, Frontend, то шаги сценария надо сопоставить с макетом;
> 3. После выведения шагов крайне рекомендуется составить диаграмму в подходящей нотации для наглядного отображения сценария;
> 4. Все вышеописанное позволит легко перейти к работе с API, БД и архитектурными компонентами решения.

### Визуализация выведенного сценария

>[!TIP]
>Для обеспечения наглядности описания сценария и эффективности последующих работ по нему, КРАЙНЕ рекомендуется подготовить диаграммы с описанием пошаговой работы сценария.
>Для этого лучше всего подходят два вида [UML](https://ru.wikipedia.org/wiki/UML) - диаграмм: **[Диаграмма Активностей](https://ru.wikipedia.org/wiki/%D0%94%D0%B8%D0%B0%D0%B3%D1%80%D0%B0%D0%BC%D0%BC%D0%B0_%D0%B4%D0%B5%D1%8F%D1%82%D0%B5%D0%BB%D1%8C%D0%BD%D0%BE%D1%81%D1%82%D0%B8)** и **[Диаграмма Последовательности](https://ru.wikipedia.org/wiki/%D0%94%D0%B8%D0%B0%D0%B3%D1%80%D0%B0%D0%BC%D0%BC%D0%B0_%D0%BF%D0%BE%D1%81%D0%BB%D0%B5%D0%B4%D0%BE%D0%B2%D0%B0%D1%82%D0%B5%D0%BB%D1%8C%D0%BD%D0%BE%D1%81%D1%82%D0%B8)**.
>
>Эти нотации диаграм позволят четко и наглядно отобразить пошагово ход исполнения выведенного сценария.

>[!CAUTION]
>Создавать диаграмму активностей можно в разных редакторах, например - [drawio](https://drawio-app.com/blog/create-uml-activity-diagrams-in-draw-io/) или [PlantUML](https://plantuml.com/ru/activity-diagram-beta)
>
>А вот для диаграммы последовательности рекомендуется использовать строго [PlantUML](https://ru.wikipedia.org/wiki/%D0%94%D0%B8%D0%B0%D0%B3%D1%80%D0%B0%D0%BC%D0%BC%D0%B0_%D0%BF%D0%BE%D1%81%D0%BB%D0%B5%D0%B4%D0%BE%D0%B2%D0%B0%D1%82%D0%B5%D0%BB%D1%8C%D0%BD%D0%BE%D1%81%D1%82%D0%B8)

|Пояснение | Диаграмма Активностей (Activity Diagram) | Диаграмма Последовательности (Sequence Diagram) | 
|:--------:|:----------------------------------------:|:-----------------------------------------------:|
| Описание и назначение диаграммы | Диаграмма активностей (видов деятельности) отображает динамические аспекты поведения системы. Эта диаграмма представляет собой блок-схему, которая наглядно показывает, как поток управления переходит от одной деятельности к другой. | Диаграмма последовательности используется для визуализации взаимодействия между объектами в системе. Это простой и удобный инструмент для демонстрации всех интеграций и взаимодействий в рамках проектируемого бизнес-процесса. |

>**Код PlantUML для рендера диаграммы активностей**

<details>

<summary></summary>
	
```
@startuml

start
partition UC1 Просмотр товаров {
    :(Предусловие)
     Просмотр товаров;
 }
partition UC2.1 Добавление товара в корзину {
    :(1) Добавление товара в корзину;
    :(2) Переход в корзину;
 }

partition UC2.2 Действия\nс параметрами\nсписка товаров {
    fork
        :(3) Просмотр добавленных товаров;
    fork again
        :(4) Изменение количества товаров;
    fork again
        :(5) Удаление товара;
    fork again
        :(6) Выбор всех товаров;
     end fork
 }
partition UC2 {
    :(7) Проверка итоговой суммы;
    :(8) Оформление заказа; 
 }
partition UC2.3 {
    :(9) Ввод и проверка данных клиента;
 }
partition UC2.4 {
    :(10)  Оплата заказа;
    :(11) Подтверждение оформления заказа;
 }
partition UC2.5 {
    :(12) Заказ передается курьеру для доставки;
    :(Завершение) 
     Заказ передается курьеру для доставки;
 }

stop
@enduml
```
</details>


>**Код PlantUML для рендера диаграммы последовательности**

<details>

<summary></summary>

```
@startuml

actor "Пользователь" as User #Application
participant "Магазин:\nВитрина"  as stfrt #Business
participant "Магазин:\nКорзина" as stcrt #Business
participant "Доставка" as Delivery #PHYSICAL

group UC1 Просмотр товаров
    User -> stfrt : Просмотр товаров
    activate stfrt
end

group UC2.1 Добавление товара в корзину
    autonumber 1
    User -> stfrt : Добавление товара в корзину
    deactivate stfrt
    User -> stcrt : Переход в корзину
    activate stcrt
    
    
end

group UC2.2 Действия с параметрами списка товаров
    
    alt Варианты действий с параметрами списка товаров
        User -> stcrt : Просмотр добавленных товаров
    else
        User -> stcrt : Изменение количества товаров
    else
        User -> stcrt : Удаление товара
    else
        User -> stcrt : Выбор всех товаров
    end
end

group UC2 Заказ товара
    User -> stcrt : Проверка итоговой суммы
    User -> stcrt : Оформление заказа
end

group UC2.3 Ввод и проверка данных клиента
    User -> stcrt : Ввод и проверка данных клиента
end

group UC2.4 Оплата заказа
    User -> stcrt : Оплата заказа
    stcrt -> User : Подтверждение оформления заказа
    
end

group UC2.5 Доставка
    deactivate stcrt
    stcrt -> Delivery : Передача заказа курьеру
    activate Delivery
end

autonumber stop
Delivery -X User : Получение заказа
deactivate Delivery

@enduml
``` 
</details>
