# 3. Требования к решению

> [!NOTE]
> Пример заполнения раздела для решения «Онлайн-заказ в магазине смартфонов».
> Каждое требование имеет ID, ссылку на вариант использования (UC) из [раздела 4](04_use_cases.md) и, при необходимости, на бизнес-правила (BR) из раздела 10. По этим ID строится матрица трассируемости в разделе 13.

## 3.1 Границы решения

**Входит в решение:** корзина, оформление заказа из корзины, ввод и проверка данных покупателя, онлайн-оплата через внешний платёжный шлюз, передача заказа во внешнюю службу доставки и отслеживание статуса заказа.

**Не входит в решение:** каталог и карточка товара (UC1 — существующая функциональность, используется как предусловие), складской учёт (остатки синхронизируются из учётной системы в `cmsDB` отдельным процессом), возвраты и обмен товара, программа лояльности.

**Допущения:**
- Покупатель авторизован до начала сценария (UC1, предусловие).
- Остатки в `cmsDB` обновляются из учётной системы не реже одного раза в 5 минут.
- Платёжный шлюз и служба доставки — внешние системы с собственным API, контракт описан в [разделе 5](05_integration_api.md).

## 3.3 Нефункциональные требования (НФТ)

> [!TIP]
> Нефункциональное требование описывает, **насколько хорошо** система должна работать. Хорошее НФТ измеримо: в нём есть число, единица измерения и условия, при которых оно проверяется.

| ID | Категория | Требование | Как проверяется |
|----|-----------|-----------|-----------------|
| NFR-01 | Производительность | Время ответа публичных методов API корзины и заказа (без учёта внешних систем): p95 ≤ 300 мс, p99 ≤ 800 мс. | Нагрузочный тест, метрики в Grafana |
| NFR-02 | Производительность | Время от нажатия «Оформить заказ» до открытия платёжной страницы: p95 ≤ 2 с. | Нагрузочный тест, RUM-метрики фронтенда |
| NFR-03 | Нагрузка | Система выдерживает 1 000 одновременных покупателей и до 20 созданий заказа в секунду в пике (распродажи) без нарушения NFR-01. | Нагрузочный тест с профилем пикового дня |
| NFR-04 | Доступность | Доступность сценария оформления заказа — не ниже 99,9% в месяц (не более 43 минут простоя). | Мониторинг доступности |
| NFR-05 | Надёжность | Потеря данных при сбое — не более 5 минут (RPO), восстановление работы — не более 1 часа (RTO). | Учения по восстановлению из резервной копии |
| NFR-06 | Надёжность | Создание заказа и инициация оплаты идемпотентны: повторный запрос с тем же ключом идемпотентности не создаёт дубль. | Автотест повторных запросов |
| NFR-07 | Надёжность | При недоступности платёжного шлюза или службы доставки заказ не теряется: вызов повторяется до 5 раз с экспоненциальной задержкой, после чего заказ помечается для ручной обработки оператором. | Тест с отключением внешней системы |
| NFR-08 | Безопасность | Все соединения — только HTTPS (TLS 1.2+). Аутентификация по access-токену JWT со сроком жизни 15 минут. | Сканирование конфигурации, ревью |
| NFR-09 | Безопасность | Данные банковских карт не попадают в систему магазина: ввод карты происходит только на странице платёжного шлюза. | Ревью архитектуры |
| NFR-10 | Безопасность | Уведомления от платёжного шлюза и службы доставки принимаются только с проверкой подписи запроса. | Автотест с неверной подписью |
| NFR-11 | Персональные данные | Обработка персональных данных — в соответствии с 152-ФЗ, хранение на серверах в РФ. В логах телефон и email маскируются. | Ревью, проверка логов |
| NFR-12 | Хранение данных | Заказы и платежи хранятся 5 лет, журнал аудита — 1 год, технические логи — 90 дней. Корзины без изменений удаляются через 30 дней. | Проверка политик хранения |
| NFR-13 | Масштабируемость | `guiGateway` и `cmsService` не хранят состояние и масштабируются горизонтально добавлением экземпляров. | Нагрузочный тест с масштабированием |
| NFR-14 | Наблюдаемость | Каждый запрос получает сквозной `traceId`, который возвращается в ответах об ошибках и пишется во все логи по цепочке вызовов. | Проверка логов по одному `traceId` |
| NFR-15 | Совместимость | Веб-интерфейс поддерживает две последние версии Chrome, Firefox, Safari, Edge и Яндекс Браузера; мобильное приложение — iOS 16+ и Android 10+. | Кросс-браузерное тестирование |
| NFR-16 | Сопровождаемость | API версионируется в URL (`/api/v1`). Изменения внутри версии — только обратно совместимые. | Проверка спецификации линтером в CI |
